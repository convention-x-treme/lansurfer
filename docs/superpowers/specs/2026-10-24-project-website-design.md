# Project website (www.lansurfer.de) — design

Status: feature-branch working spec. Harvest into canonical docs before merge (see "Canonical doc updates").
Issue: #226

## Problem

LANsurfer has no public project website. The README carries the pitch; the in-app landing page (`GET /` logged out) belongs to one installation and must not become a marketing page. We want a static, bilingual (EN/DE) website at `https://www.lansurfer.de` that introduces LANsurfer, links the demo, and explains self-hosting.

## Decisions (maintainer, 2026-10-24)

| Topic | Decision |
| --- | --- |
| Shape | Separate binary `cmd/lansurfer-site`, single subcommand `build --out DIR`. No `serve`. |
| Release | Not part of GoReleaser artifacts or the Docker image. |
| Hosting | GitHub Pages via Actions, custom domain `www.lansurfer.de`. |
| Deploy trigger | Only when an official release is published (`release: published`) plus manual `workflow_dispatch` with a tag input. |
| Languages | `/` English, `/de/` German. Language switch links the counterpart page. `hreflang` alternates. No auto-redirect. |
| Content | Hero (tagline, otter, CTA "Try the demo"), What is LANsurfer + How it works (3 steps), screenshots (dark/light), self-hosting, GitHub/get involved/AGPL, Imprint + Privacy. |
| Screenshots | Generated by a Playwright task against the existing `internal/web/browsertest` fixture; PNGs committed. |
| Legal texts | Markdown files in the repo. |
| Privacy | No cookies, no analytics, no JavaScript, self-hosted fonts and icons. |

## Terminology

"Project website" = www.lansurfer.de (this spec). "Landing page" stays the in-app logged-out `GET /` from PRODUCT §6. Never mix them. Add "Project website" to `docs/TERMINOLOGY.md`.

The website is not product UI: PRODUCT §5 "UI is English-only" stays true for the application. The German website pages are not localization infrastructure for the app; nothing under `internal/` gains i18n.

## Implementation shape

- `cmd/lansurfer-site/main.go`: parses `build --out DIR [--release vX.Y.Z]`; refuses a non-empty `DIR` (no accidental overwrite); renders pages, copies assets. `--release` pins self-hosting links (`docs/SELF_HOSTING.md` at that tag, release page); default links target `main` and the releases list.
- `cmd/lansurfer-site/pages.templ`: one `Page` layout and the home/legal bodies. Language strings live in a plain Go struct per language (`content.go`, `var en = Copy{...}`, `var de = Copy{...}`). No i18n library, no message catalog.
- Legal: `cmd/lansurfer-site/content/{en,de}/{imprint,privacy}.md`, embedded, rendered with goldmark (already a dependency, same defaults as `internal/platform/legal`: raw HTML omitted).
- Styling: reuse the app stylesheet. Add `@source "../../cmd/lansurfer-site/**/*.templ";` to `web/src/app.css` so Tailwind keeps the site's classes. Cost: a few hundred bytes in the app CSS; avoids a second CSS pipeline. ponytail: shared stylesheet; split into `site.css` only if site-only classes grow noticeably.
- Branding: tagline, product name, colors, and "Powered by" attribution from `internal/web/branding`. Assets read from the existing `internal/web/assets` embed FS. Mascot/logo via existing `dist/images`; add an image there only if the needed pose is missing.
- Theme: no toggle (no JS). `<html>` follows `prefers-color-scheme` via the DaisyUI theme selection already present in the stylesheet; screenshots use `<picture><source media="(prefers-color-scheme: light)">` so they match the visitor's theme.
- Head: `lang`, canonical URL `https://www.lansurfer.de/...`, `<link rel="alternate" hreflang="en|de|x-default">`, description meta, favicon from bundled icons.
- No `<script>`, no cookies, no external origins except plain links (GitHub, demo).

## Screenshots

`task site:screenshots` runs Playwright (already installed) with a dedicated `playwright.site.config.ts` whose `webServer` is the existing browsertest fixture (`go run ./internal/web/browsertest`). Captures, each dark + light at 1280×800:

1. logged-out landing page `/`
2. Game Requests list (signed-in fixture)
3. a Game Request lobby

Writes `cmd/lansurfer-site/static/screenshots/{name}-{dark|light}.png`. This is a generator, not a test; it lives in `tools/site-screenshots/` (not `web/tests`, which AGENTS.md restricts to interaction regressions). Rerun when UI changes before a release.

## CI / deployment

New workflow `.github/workflows/site.yml`:

- triggers: `release: types: [published]`, `workflow_dispatch` (input `tag`).
- checkout the release tag, setup Go, `go run ./cmd/lansurfer-site build --out _site --release <tag>`, `actions/upload-pages-artifact`, `actions/deploy-pages`.
- permissions: `pages: write`, `id-token: write`, `contents: read`; environment `github-pages`.
- No Node step: CSS/templ output is committed.

Operator one-time steps (not code, record in the issue): Pages source = GitHub Actions; custom domain `www.lansurfer.de`; DNS `www CNAME convention-x-treme.github.io`; enforce HTTPS; apex `lansurfer.de` redirect to `www` at the DNS provider.

## Verification

- Go test `cmd/lansurfer-site/main_test.go`: build into `t.TempDir()`; assert every expected page exists; each page has `lang`, canonical, and hreflang alternates pointing at existing files; every local `href`/`src` resolves to a file in the output; no `<script` in any page. This catches broken links and language-pair drift.
- Smoke: build locally, open `index.html` and `de/index.html` in the browser in dark and light, check layout at mobile width.
